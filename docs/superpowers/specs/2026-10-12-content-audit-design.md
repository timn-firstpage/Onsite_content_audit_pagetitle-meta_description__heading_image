# Onsite content audit design

Build a standalone `onsite-audit-content` skill for checklist items 17.1–20.2, using the working Multica extraction logic supplied by the owner. Align the repository with the HTTPS/robots/sitemap series: root SKILL.md, shared site/source/mcp/budget/output config, saved-crawl handover, local findings and a portable Excel report. No changes to sibling repositories or user-global installations.

The module consumes Screaming Frog CSV exports only. An agent obtains those exports from the already loaded/saved crawl using verified SF capabilities. New crawl preparation belongs to sf-shared-config; opening a supplied saved crawl does not authorize recrawling. This module makes no website requests, installs no MCP server and does not manipulate a shared SF session.

Reuse native SF missing/duplicate/multiple reports, the pure same-page H1 collision refinement, >580px titles and >200*1024 byte images. Owner confirmed >155 characters for descriptions; remove the old 880px rule. Exact target URL exclusions apply only to 17.1/18.1; inspect existing session/config/task records for an explicitly identified target list, but never infer targets from Missing rows. No supplied list means no exclusions and a disclosed limitation. 19.1 checks H1 presence only, not keyword relevance; 20.1 empty alt remains a candidate needing decorative-image review.

Produce a fresh `{site name}_content_audit_{YYYY-MM-DD}.xlsx`: Checklist plus the twelve detail sheets named by the owner. Checklist columns: Item No., Item Name, Initial Check, Findings, Instruction. Results √/X/Human Check; X plus an evidence gap remains X with a visible limitation. Every confirmed issue row remains available; no rows for unknown-only items, header-only clean tabs. Keep count/scope/provenance in findings.json and manifest.json. No whole-onsite template, unrelated checks, Review rollover, annotation merge or template downloads.

Validate files, CSV structure and per-item needed headers; distinguish absent, valid empty and unusable exports. Missing/malformed numeric or Indexability values cannot prove a pass. Image absence/partial size data yields Human Check unless known issues already prove X. Literal spreadsheet text must not execute formulas; output and JSON files refuse overwrite. Date is explicit or computed in configured timezone. Config relative paths resolve from the config file, not CWD; customer evidence stays ignored.

Verification: regression tests for native duplicates, H1 collisions, thresholds, target exclusion, partial evidence, external image counts, site mismatch, report schema/literal strings/no overwrite, config reuse and timezone. End-to-end synthetic CSV → findings/manifest → XLSX read-back. Live Multica/SF execution is outside local verification.
